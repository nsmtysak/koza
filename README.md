# Kōza（口座）

高級クラブのホステス一名のために作った顧客管理 PWA。

既存の顧客管理アプリとの違いは一点に絞ってある。

> **記録を貯める道具ではなく、締め日に目標へ届かせるために「今日どの日を埋めにいくか」を出す道具。**

今日お迎えするお客様は、今日つくったのではない。数日前の一手の結果である。
だからこのアプリの中心は顧客一覧ではなく **枠（14日の盤面）** にある。

---

## 1. 動かす

ビルド不要。`index.html` を開けば動く（`file://` でも可）。

```bash
npx serve . -l 8731
```

AI 機能を使うには GAS プロキシが要る（→ `DEPLOY.md`）。
プロキシ未設定でも、記録・顧客管理・盤面・逆算は動く。

## 3. データ

localStorage（名前空間 `koza2.`）に 6 つの実体。画像だけ IndexedDB（`koza-blobs`）。

| 実体 | 中身 |
|---|---|
| `Customer` | お客様。名刺・家族・趣味・嗜好・**口座** |
| `Visit` | 来歴。同席者と役割、話した内容、金額、口実 |
| `Touch` | 接点。**お誘い**（型・狙う日・結果）、贈答、連絡 |
| `Appointment` | 来店予定。日付・確度（確定／お約束／狙う） |
| `Goal` | 月の目標。締め日で期間が決まる |
| `Brief` | AI の準備と、その結果の評価 |

**サーバーに顧客データは無い。** GAS プロキシは中継のみで保存もログ出力もしない。

### 口座（最重要）

`customer.account_owner` は `self` / `mama` / `other` / `free`。未設定は自分の口座として扱う。

永久指名制の店では口座は信頼関係そのもので、**他の方の口座のお客様にこちらから連絡するのは越境**にあたる。
そのため次を全経路で遮断してある。

- `Insight.callList()` — 声かけ候補から除外
- `Plan.candidates()` — 逆算の対象から除外
- `Invite.open()` — お誘い画面を開かせない
- `People` の顧客カード — お誘い系ボタンを描画しない
- `Plan.aftercare()` — お礼の対象から除外
- `handleBrief`（GAS）— `message_drafts` を空にさせ、係を立てる書き方に限定

売上の実績（`Plan.progress().actual`）も、主客が自分の口座の来店だけを数える。
ヘルプで付いた席は `help_visits` に分離。

## 4. 逆算エンジン（`js/plan.js`）

```
目標 − 実績 − 予定の見込み ＝ 不足
  → 不足 ÷ 平均単価 ＝ 必要な組数
  → 14日の盤面から埋める日を選ぶ（空き・その方の来店曜日・締めに間に合うか）
  → 声をかける締切 ＝ 狙う日 − リードタイム
  → 締切が今日または過去なら、それが今日の仕事
```

各お客様について記録から推定する値。

| 指標 | 出し方 | 記録が足りないとき |
|---|---|---|
| リードタイム | 誘い → 来店 の日数の平均 | 設定の既定値（初期4日／同伴5日）／画面に「目安」と明示 |
| お越しになる割合 | came ÷ (came + missed) | ラプラス平滑化。0%・100%と言い切らない |
| 来店しやすい曜日 | 来歴の曜日分布（2回以上） | 使わない |
| 効いた誘いの型 | 型別の came 率 | 全体の傾向 → なし |
| 見込み単価 | その方の平均（主客配分） | 全体平均 |

見込みは確度で割り引く（確定 1.0 / お約束 0.6 / 狙う 0.3）。

### 誘いの決着

逆算の精度はここで決まる。`Store.addVisit()` が来店を受け取った時点で、
21日以内の未決着のお誘いのうち**直近の1件を `came`**、それより前を `superseded` にする。
期日を過ぎたものは起動時の `settleOverdueInvites()` が `missed` にする。

## 5. AI に任せている範囲

事実の計算は端末、判断と言葉は AI。この線引きは崩さない。
根拠を説明できない提案は使われないため。

| mode | モデル | 役割 |
|---|---|---|
| `structure` | 高速 | 話し言葉 → 来歴＋プロフィール追記＋**来店予定** |
| `card` | 高速 | 名刺画像 → 顧客情報 |
| `brief` | 熟考 | 準備。話題・確認・**手当て**・**信を落としかねない点**・**仕込む質問** |
| `plan` | 熟考 | 逆算した段取り。今日やること／この先動く日／今は動かない方 |
| `invite` | 熟考 | お誘いの文面を型ごとに3案（効く理由・危うさつき） |

出力は全て structured outputs（`output_config.format.json_schema`）。

### お誘いの型（`inviteStyles()`）

`info` お知らせにする ／ `deadline` 期限をつける ／ `star` 相手を主役に ／
`rely` 教えを乞う ／ `match` 会わせたい方がいる ／ `choice` 二択で伺う ／
`meal` お食事に誘う ／ `report` 近況をお伝えする

禁止も明示してある。営業の匂い、誰にでも送れる文、既読・返事の催促、
情に訴える表現、他店・他のホステス・他のお客様の話、ご年齢。

### 客観表現の規則（`objectivityRule()`）

記録が万一お客様の目に触れうる前提で、感情語・内面の推測・
「〜そうだった」「〜が見られた」を禁じている。
**原文に観察された行動が無ければ `observation` は空文字**。捏造は明示的に禁止。

## 6. お客様に迷惑をかけないための歯止め

売上より優先する。順に効く。

| | 実装 |
|---|---|
| 他の方の口座への接触 | 全経路で遮断（→ 3節） |
| しつこさ | 設定の日数以内に連絡した方・返事待ちの方を候補から外す。理由を「今は間を置く方」に表示 |
| 鉢合わせ | 同日に `avoid_pair` の方・同じ会社の方がいると確認を挟む |
| 送信時刻 | 設定の「送らない時間」に入っていれば警告（初期 23時〜9時） |
| お礼 | 来店翌日のお礼を売上の逆算より先に置く。紹介者へのお礼も自動で立てる |
| 覗き見 | 4桁の暗証番号。SHA-256＋ソルトで保管。離席（既定3分）で閉じ直す |

暗証番号は覗き見を止めるためのもので、端末を解析されれば記録は読める。
`HANDOFF.md` にもその通り書いてある。

## 7. 版の管理

`index.html` の `?v=N`、`sw.js` の `SHELL` と `VERSION` を必ず揃える。
ずれると古い JS がキャッシュから配られる（実際に2度踏んだ）。

現在：**v11**

## 8. 未確認のまま作った前提

使う本人にヒアリングできない前提で組んである（間に人が入るため直接やり取りできない）。
本人にしか分からない値は、**すべて設定画面から変えられる**ようにしてある。
初期値は一般的な形に寄せてあるだけで、根拠のある数字ではない。

| 設定 | 初期値 | 根拠 |
|---|---|---|
| 締め日 | 月末 | 未確認 |
| 営業曜日 | 月〜土（日曜休み） | 法人接待が中心＝企業が休む日は客が来ない |
| 祝日・年末年始・お盆 | すべて休み | 同上。範囲も設定で変えられる |
| 指名制度 | 永久指名制 | この業態に多いと聞いている。未確認 |
| 同伴の入店締め・開店時刻 | 空 | 未確認 |
| 「係」「ヘルプ」の呼び方 | そのまま | 店によって違う |
| ご連絡の間隔 | 3日 | 経験則 |
| お返事を待つ日数 | 10日 | 経験則 |
| 送らない時間 | 23時〜9時 | 経験則 |
| リードタイムの既定 | 4日（同伴5日） | 記録が2件たまれば本人の実績で置き換わる |

祝日は `js/holiday.js` で計算している（外部に問い合わせない）。
春分・秋分の近似式は 1980〜2099 年で官報と一致する。振替休日・国民の休日も出る。

このほか、**顧客データが店の資産にあたるか**が未確認。
そのため設定の「使用状況」は件数のみで、お客様の名前や会話の中身を一切含まない。
